# InterviewVault

**Learn from every interview. Never repeat a mistake.**

InterviewVault is a full-stack, AI-powered personal interview experience manager.
Log the interviews you actually had — company, role, rounds, questions, and your
real answers — and get structured Gemini feedback (correct answer, a better
response, the explanation, and the concepts you missed) for every question.

> **AI rule:** Gemini is called **only from the backend** and **only ever sees your
> own question and answer**. It never searches the web, never pulls questions from
> other platforms, and never fabricates experiences.

---

## Features

- **Authentication** — register / login / logout with JWT access tokens + rotating refresh tokens, bcrypt-hashed passwords
- **Interview management** — create/edit/delete your own interviews with company, role, type, date, and status
- **Rounds & questions** — nested round structure (Technical, HR, Manager…) with per-question answers
- **AI analysis** — one tap sends your question + answer to Google Gemini and stores a structured 5-part markdown report per question
- **Community question library** — questions from all users appear automatically after save, with search, filters, and newest-first sorting
- **Private answers** — candidate answers, AI feedback, notes, identity, and account data are excluded from community APIs
- **Dashboard analytics** — total/selected/waiting/rejected counts, success rate, monthly activity chart, company distribution, recent activity
- **Profile** — update display name, change password

## Architecture

```

        │  HTTPS + Bearer JWT (access token)
        ▼
  FastAPI (REST /api/v1 on Render/Railway)
        │
        ├── PostgreSQL (Supabase)   — relational data
        └── Google Gemini           — AI analysis, server-side only
```

```

  src/                          app/
  ├── components/ui            ├── ai/           Gemini integration
  ├── components/layout        ├── authentication/  security + deps
  ├── features/                ├── database.py   engine + session
  │   ├── auth                 ├── models/       SQLAlchemy ORM

  └── pages/                   ├── config.py     settings (.env)

```

## Database schema

```
users (id PK, name, email UNIQUE, password_hash, created_at)
  │ 1─N
  │
companies (id PK, name UNIQUE, created_at)
  │ 1─N
  ▼
interviews (id PK, user_id FK, company_id FK, role, date, status, created_at)
  │ 1─N
  ▼
rounds (id PK, interview_id FK, name, created_at)
  │ 1─N
  ▼
questions (id PK, round_id FK, question, user_answer, ai_answer, created_at)

refresh_tokens (id PK, user_id FK, token_hash UNIQUE, expires_at, created_at)
```

- All IDs are UUIDs generated by Postgres (`gen_random_uuid()`).
- `interviews.user_id`, `interviews.company_id`, `rounds.interview_id`, `questions.round_id` are indexed.
- Deleting an interview cascades to its rounds and questions; deleting a company is restricted while referenced.
- `ai_answer` is stored as markdown with **fixed `##` headings** so the frontend renders structured cards.

## Getting started

### Prerequisites

- Node.js 18+ with npm
- Python 3.12+
- PostgreSQL 14+ (local or Supabase)
- A Google AI Studio API key only if you want to use AI answer analysis

The frontend and backend run as two separate development processes. Start the
backend first, then start Vite in a second terminal. Vite proxies `/api` requests
to `http://localhost:8000`; the backend serves the API under `/api/v1`.

### 1. Create a PostgreSQL database

Create a database named `interviewvault` locally, or create a Supabase project and
copy its PostgreSQL connection string. The backend creates its tables at startup.

Use a SQLAlchemy/psycopg connection URL, for example:

```text
postgresql+psycopg://postgres:YOUR_PASSWORD@localhost:5432/interviewvault
```

For Supabase, use the connection string supplied by the project and ensure it uses
the `postgresql+psycopg://` driver prefix.

### 2. Configure and run the backend

In PowerShell:

```powershell
cd backend
py -3.12 -m venv .venv
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Edit `backend/.env` and set at least `DATABASE_URL` and a long random `JWT_SECRET`.
Set `GEMINI_API_KEY` to enable AI evaluations; the rest of the app can run without
it. Then start the API from the `backend` directory:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

The API is at `http://localhost:8000`, the interactive docs are at
`http://localhost:8000/docs`, and its health check is at
`http://localhost:8000/api/v1/health`.

On macOS/Linux, use `python3.12 -m venv .venv`, `cp .env.example .env`, and
`.venv/bin/python -m pip install -r requirements.txt`; start the API with
`.venv/bin/python -m uvicorn app.main:app --reload`.

Backend `.env` keys:

| Variable                     | Description                                   |
|------------------------------|-----------------------------------------------|
| `DATABASE_URL`               | `postgresql+psycopg://…` (local or Supabase)  |
| `JWT_SECRET`                 | Long random string; generate with `python -c "import secrets; print(secrets.token_urlsafe(48))"` |
| `ACCESS_TOKEN_EXPIRE_MINUTES`| 15                                            |
| `REFRESH_TOKEN_EXPIRE_DAYS`  | 7                                             |
| `GEMINI_API_KEY`             | from https://aistudio.google.com/apikey        |
| `GEMINI_MODEL`               | `gemini-3.6-flash`                            |
| `ALLOWED_ORIGINS`            | Comma-separated browser origins for CORS       |
| `ADMIN_EMAILS`                | Optional comma-separated emails to promote to admin |

> Tables are auto-created on first boot (`create_all`). For production, switch to
> Alembic migrations.

#### Existing database migration

If upgrading a database that already has the original InterviewVault schema and
`001_community_sharing.sql` applied, run
`backend/migrations/002_community_question_workflow.sql` once in the database's
SQL console (for example, the Supabase SQL Editor) before starting the updated
backend. It adds the interview type, per-question difficulty, an idempotency key,
and the `in_progress` status without deleting existing data. A brand-new database
can be created from the current SQLAlchemy models on first startup and does not
need this upgrade migration.

### 3. Configure and run the frontend

Open a second terminal at the project root and run:

```powershell
cd frontend
Copy-Item .env.example .env
npm install
npm run dev
```

Open the Vite URL shown in the terminal (normally `http://localhost:5173`). Keep
the backend process running in its own terminal. For a production frontend build,
run `npm run build`; `npm run lint` runs the TypeScript check.

The generated `frontend/.env` should keep `VITE_API_URL=/api/v1` for local
development. For deployment, set it to the deployed API base URL ending in
`/api/v1`.

## API overview

Base path: `/api/v1`. All endpoints except auth/docs require
`Authorization: Bearer <access_token>`.

```
POST   /auth/register          201 {access_token, refresh_token, user}
POST   /auth/login             200 {access_token, refresh_token, user}
POST   /auth/refresh           200 {access_token, refresh_token}   (rotates)
POST   /auth/logout            204  (revokes all refresh tokens)
GET    /auth/me                200 user
PATCH  /auth/me                200 user            {name}
POST   /auth/change-password   204                  {current_password, new_password}

GET    /companies              200 [{id, name}]
POST   /companies              201 {id, name}

GET    /interviews             200 [{id, user_id, company, role, date, status, created_at}]
       ?status=&company=&q=&date_from=&date_to=
POST   /interviews             201 {…}             {company_id | company_name, role, date, status}
POST   /interviews/experience  201 interview with rounds/questions (atomic, idempotent)
POST   /interviews/evaluate-answer 200 {score, feedback, model} (authenticated; backend-only Gemini)
GET    /interviews/{id}        200 {…, rounds: [{…, questions}]}
PUT    /interviews/{id}        200 {…}
DELETE /interviews/{id}        204
POST   /interviews/{id}/rounds 201 {id, interview_id, name}

PUT    /rounds/{id}            200
DELETE /rounds/{id}            204

POST   /rounds/{id}/questions  201 {id, round_id, question, user_answer, ai_answer}
POST   /questions/{id}/analyze 200 {question: {…, ai_answer}}   (Gemini)
PUT    /questions/{id}         200
DELETE /questions/{id}         204
GET    /questions/search       200 [{…}]  ?q=&company=&status=&sort=newest|oldest

GET    /community/questions    200 safe question cards with filters:
       ?q=&company=&role=&interview_type=&round_name=&category=&difficulty=&sort=newest|oldest&page=
GET    /community/companies    200 companies that have community questions

GET    /analytics/summary      200 {total, selected, waiting, rejected, success_rate, recent}
GET    /analytics/monthly      200 [{month, total, selected, rejected}]  (last 12 months)
GET    /analytics/companies    200 [{company, count}]
```

Errors are consistent:

```json
{ "detail": { "code": "EMAIL_TAKEN", "message": "An account with this email already exists." } }
```

Interactive docs: `http://localhost:8000/docs` (Swagger).

## Testing

```bash
# Backend — full API smoke test (needs DATABASE_URL; AI step auto-skips without GEMINI_API_KEY)
cd backend
.venv\Scripts\python.exe scripts\smoke_test.py

# Frontend — typecheck
cd frontend
npm run lint        # tsc --noEmit
npm run build
```

Manual checks to cover: register two users → save an interview with multiple
questions → verify questions appear in Community for both users → verify answers,
AI feedback, notes, and identity are absent from community responses → verify each
user only sees their own interviews → filter/search community questions → update
status → delete → logout → verify 401s on protected routes without a token.

## Deployment

### Frontend (Vercel)

1. Push the repo to GitHub.
2. Import `frontend/` as a new Vercel project (root directory: `frontend`).
3. Add env var `VITE_API_URL=https://your-backend.onrender.com/api/v1`.
4. Build command `npm run build`, output `dist`.

### Backend (Render / Railway)

1. Create a new web service from the repo, root directory `backend`.
2. Build: `pip install -r requirements.txt`. Start: `uvicorn app.main:app --host 0.0.0.0 --port $PORT`.
3. Set env vars: `DATABASE_URL`, `JWT_SECRET`, `GEMINI_API_KEY`, `ALLOWED_ORIGINS=https://your-app.vercel.app`.

### Database (Supabase)

1. Create a project → copy the connection string from **Settings → Database**.
2. Set `DATABASE_URL=postgresql+psycopg://postgres.<ref>:<password>@<host>:5432/postgres?sslmode=require`.
3. The backend auto-creates tables on first boot.
